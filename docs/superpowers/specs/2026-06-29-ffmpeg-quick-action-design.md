# Design: macOS ffmpeg Quick Action — Media Converter

**Date:** 2026-06-29
**Status:** Approved (brainstorming complete)

## Goal

A macOS app plus a Finder **Quick Action** that converts selected media files with ffmpeg.
Right-click media in Finder → Quick Actions → "Convert Media" → a single-window UI to choose
container/codecs/quality → ffmpeg runs → converted files appear next to the originals.

Built for the author's own Mac first, but structured so it can be shared later without rework.

## Locked decisions (from brainstorming)

- **Architecture:** SwiftUI container app (**non-sandboxed**) + **Action Extension** (`.appex`, sandboxed —
  required for extensions). The extension registers the Finder Quick Action and hands the selected file
  paths to the app, which owns all UI and conversion logic.
- **ffmpeg source:** use the system Homebrew `ffmpeg`/`ffprobe` now, behind an `FFmpegLocator` seam so a
  bundled binary can be swapped in later.
- **UI:** a single control panel with smart, **iPhone-ready defaults**. **No presets.** Just hit Convert
  for the common case; adjust controls when needed.
- **iPhone compatibility:** when the selected combo is iOS-capable, the engine **automatically** injects
  the Apple-safe muxing flags. A live badge shows ready / not-compatible (with reason).
- **Project generation:** **XcodeGen** (`project.yml` → `.xcodeproj`), so the two-target setup is
  reproducible and reviewable in git. (XcodeGen is installed.)
- **Distribution:** personal / Developer ID; non-sandboxed app is acceptable. (Mac App Store would later
  require sandboxing the app — explicitly out of scope for v1.)

## Architecture & components

```
MediaConverter.xcodeproj  (generated by XcodeGen from project.yml)
├─ MediaConverter            SwiftUI app · non-sandboxed
│   ├─ FFmpegLocator         finds ffmpeg/ffprobe (Homebrew now, bundled later)
│   ├─ MediaProbe            runs ffprobe → duration + stream codecs per file
│   ├─ ConversionSettings    the model the UI edits
│   ├─ ArgumentBuilder       pure: (settings, input, output, probe) → [ffmpeg args]
│   ├─ IPhoneCompatibility   pure: (settings, probe) → (compatible, reason)
│   ├─ OutputNamer           pure: collision-free output path
│   ├─ ConversionEngine      runs ffmpeg Process, parses progress, cancellable, sequential queue
│   └─ UI (SwiftUI)          conversion window, file list, controls, progress, error sheet
└─ ConvertQuickAction.appex  Action Extension · sandboxed
    └─ thin: receive file URLs → write path list to App Group → launch app via URL scheme
```

Shared between targets:
- **App Group** `group.<bundle-id>` — the extension writes the selected file path list (JSON) here.
- **Custom URL scheme** `mediaconverter://convert` — how the extension wakes the app.

### Data flow

```
Finder: right-click media → Quick Actions → "Convert Media"
   │
   ▼
ConvertQuickAction.appex
   • reads selected file URLs from the NSExtensionItem attachments
   • writes the path list (JSON) into the shared App Group container
   • opens  mediaconverter://convert  and completes the request
   │
   ▼
MediaConverter.app
   • on URL open, reads the pending path list from the App Group container
   • ffprobes each file → duration + source video/audio codec
   • shows the conversion window (controls pre-filled to iPhone-ready defaults)
   • on Convert: ArgumentBuilder → ffmpeg via Process, parse `-progress pipe:1`
   • writes output next to each input (never silently overwriting)
```

Because the app is **non-sandboxed**, it reads inputs and writes outputs directly — no
security-scoped-bookmark plumbing. The extension only needs to pass plain file paths.

## Conversion model & ffmpeg mapping

| Field | Options | ffmpeg mapping |
|---|---|---|
| **Container** | mp4, mov, m4v, mkv, webm · m4a, mp3 (audio-only) · gif | output file extension + muxer |
| **Video codec** | H.264, HEVC, AV1, VP9, **Copy**, None | `-c:v libx264` / `libx265` / `libsvtav1` / `libvpx-vp9` / `copy` / (drop) |
| **Audio codec** | AAC, MP3, ALAC, Opus, **Copy**, None | `-c:a aac` / `libmp3lame` / `alac` / `libopus` / `copy` / `-an` |
| **Quality** | slider (CRF) | `-crf N` software · VideoToolbox uses `-q:v` instead (see below) |
| **Audio channels** | Same as source, Mono, Stereo, 5.1 | `-ac 1` / `2` / `6` · skipped when Copy/None |
| **Audio bitrate** | **Auto**, 96, 128, 160, 192, 256, 320 kbps | `-b:a Nk` · omitted for Auto · **N/A** for Copy, None, ALAC |
| **Hardware (VT)** | toggle | swaps to `h264_videotoolbox` / `hevc_videotoolbox` |

### Quality / CRF defaults (software encoders)

| Codec | Flag | Default | Range (lower = better) |
|---|---|---|---|
| H.264 (libx264) | `-crf` | 23 | 0–51 |
| HEVC (libx265) | `-crf` | 28 | 0–51 |
| AV1 (libsvtav1) | `-crf` | 30 | 0–63 |
| VP9 (libvpx-vp9) | `-crf` + `-b:v 0` | 31 | 0–63 |

VideoToolbox encoders (`*_videotoolbox`) do **not** support CRF — the quality slider maps to `-q:v`
(constant-quality) for them. This branch lives in `ArgumentBuilder`.

### Audio bitrate — what "Auto" means (measured on ffmpeg 8.1.2)

Omitting `-b:a` does **not** preserve the source bitrate and does **not** error — it applies the
encoder's own default:

| Encoder | No `-b:a` → result |
|---|---|
| AAC | ~128 kb/s |
| MP3 (libmp3lame) | 128 kb/s CBR |
| Opus (libopus) | ~120 kb/s (auto by channels/rate) |
| ALAC | flag ignored entirely (lossless, content-determined) |

So "Auto" = encoder default; the UI shows a hint (e.g., "Auto ≈ 128k for AAC") so it isn't a surprise.
The bitrate control is disabled for Copy, None, and ALAC.

### iPhone-compatibility rule

A combo is **iPhone-ready** when:
- **Container** ∈ { mp4, mov, m4v, m4a }, AND
- **Video** ∈ { H.264, HEVC }, AND
- **Audio** ∈ { AAC, MP3, ALAC }.

`Copy` and `None` resolve against the **actual source stream** (from the ffprobe we already run), e.g.
Copy is iPhone-ready only if the source stream is itself H.264/HEVC (video) or AAC/MP3/ALAC (audio).

When the combo qualifies, `ArgumentBuilder` auto-injects:
- `-movflags +faststart` (instant playback / progressive streaming)
- H.264 re-encode: `-pix_fmt yuv420p -profile:v high`
- HEVC re-encode: `-tag:v hvc1 -pix_fmt yuv420p` (the Apple tag most tools forget — without it iPhone
  refuses to play HEVC)
- HEVC **Copy** into mp4/mov: still apply `-tag:v hvc1`

Outside that set (AV1, VP9, Opus, MKV/WebM) the badge reads **"Not iPhone-compatible"** with the reason.
AV1 is excluded deliberately — only iPhone 15 Pro and newer decode it, so "always works" can't be promised.

### Combo validation

Not every codec fits every container (e.g., H.264 in WebM is invalid). The UI offers only valid codec
options per selected container, and a pre-flight check runs before ffmpeg is invoked.

## UI flow, batch, output & errors

**UI.** One window: input file list (each with detected source codec + duration from ffprobe), the control
panel (table above) pre-filled to iPhone-ready defaults, the live **iPhone-ready badge**, an output-location
note, and **Convert** + progress. The window also accepts **drag-and-drop / Open**, so the app is usable
standalone and testable without the extension.

**Batch.** Multiple selected files share one settings panel. Conversions run **sequentially** through a
queue (ffmpeg already saturates cores), with a per-file progress row plus overall progress.

**Output.** Written next to each input as `<name>.<newext>`. Collisions (same-container re-encode, or a
pre-existing file) get a clear suffix, e.g. `clip (converted).mp4` — **never a silent overwrite**.

**Errors & edge cases.**
- ffmpeg/ffprobe not found → friendly prompt to install via Homebrew or point at a path (the `FFmpegLocator`
  seam; chosen path persists in `UserDefaults`).
- ffmpeg exits non-zero → capture the stderr tail, show a per-file error, continue the rest of the batch.
- Invalid combo → disabled in the UI + caught by pre-flight validation.
- Cancel → terminate the `Process` and delete the partial output file.

## Testing

Core logic is pure and unit-tested:
- **ArgumentBuilder** — settings → ffmpeg args, including iPhone-flag injection, Copy/None handling, and
  ALAC-bitrate-disabled.
- **IPhoneCompatibility** — settings + probe → (compatible, reason), including Copy-resolves-against-source.
- **MediaProbe parsing** — ffprobe output → duration + codecs (fixture text).
- **Progress parsing** — `-progress pipe:1` lines → fraction (fixture text).
- **OutputNamer** — collision handling.

SwiftUI views and the extension handoff get manual QA; logic stays out of views so the testable core stays
pure. Optional: one integration test that runs real ffmpeg on a generated clip and asserts the output codec
(gated on ffmpeg being present).

## Out of scope (v1) / future

- Presets (explicitly dropped).
- Output-folder picker (v1 = same folder as input).
- Trimming, resolution scaling, fps control, custom-args passthrough.
- Bundled ffmpeg binary, Developer ID signing, notarization, Mac App Store / app sandboxing.

## Risks / to verify during implementation

- **Extension → app launch API on macOS 26.** Preferred: `NSExtensionContext.open(_:)` to fire the
  `mediaconverter://` URL. Some `NSWorkspace` methods are `NS_EXTENSION_UNAVAILABLE`, so confirm the exact
  supported call; fallback is registering the app as a document handler and using an available open API, or
  shaping the extension as a Service. Verify before committing to the handoff code.
- **Quick Action visibility / signing.** An Action Extension must be code-signed (ad-hoc is fine locally) and
  the app run at least once for the Quick Action to appear; may need a toggle in System Settings → Extensions.
